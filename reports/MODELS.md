# 模型选择与验收

模型负责理解自然语言、识别图中文字和交易边界、绑定日期/账户、判断收入/支出/退款/转账、结合上下文提问。金额求和、资产与负债、贷款本金、物品平均成本和图表全部由程序计算。这个任务不是只做数学，便宜的多模态模型可以作为首选，但必须通过实际账单验收。

## 必需能力

- Responses API兼容接口，支持input_text、input_image与data URL图片。
- text.format.type=json_object，稳定生成规定的JSON对象。
- 中文文字与截图理解，含多笔交易的排版、日期和正负号。
- 足够的上下文和输出长度；文字请求最多4000输出token，图片最多8000。当前最多50条可见明细，模型可接受额度须与服务匹配。

默认AI_REASONING=none，不发送reasoning参数。模型明确支持时再使用low/medium/high。模型名称是用户填写的供应商标识，程序不绑定特定品牌、不验证供应商宣传的型号，也不保证不同服务对同名模型行为一致。单独具有多模态能力但只有Chat Completions接口的模型不能直接接入本版。

## 最小连接检查

运行npm run connections：飞书凭证验证、文字“奶茶支出20元”、程序生成的示例收据图。验证JSON金额20.00和expense方向，结果不记录收支，不发送飞书消息。测试失败不输出密钥、服务响应体或用户账目。它用于排查接口兼容和基本读图能力，不证明复杂账单正确。

## 换模型验收

先在独立目录中配置一个不绑定正式飞书用户的测试实例，使用空账本和不含个人信息的图片。至少检查：

| 场景 | 必须满足 |
| --- | --- |
| 奶茶20、妈妈红包30 | 分类合理，支出/收入方向正确 |
| 券12.8退款 | 关联原支出，不当新收入，累计不超过原金额 |
| 还花呗100 | 本金是账户转账，不重复记消费 |
| 无年份、多笔截图 | 日期与各交易块对应，缺年份/账户保持未知 |
| 月度汇总、余额、授信 | 不生成独立交易 |
| 相似重复行 | 保留并询问，不自动删除 |
| 模糊金额、裁切记录 | 不猜数字，不补造交易 |
| 连续补充后确认 | 补字段不等于入账，确认后只执行一次 |

检查回执及最终数据库，不能只看回答听起来是否合理。图片方案有疑点时先取消，避免为了测试而导入真实账本。模型费用主要来自提示词上下文、图片和输出，短消息的金额很小不代表请求token很少；实际单价由用户API服务决定。

代码使用OpenAI SDK调用Responses，不要求必须使用OpenAI模型；兼容供应商需满足上述契约。参考官方接口文档：https://platform.openai.com/docs/api-reference/responses 。本版不提供未经实际验收的模型价格排名。
