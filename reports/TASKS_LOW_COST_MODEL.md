# 下一版任务：低成本模型与无模型记账

执行顺序：先完成当前 Windows 版本的实现、验收和发布，再开始本任务。版本号沿用项目实际进度，不预先指定。

## 目标

不配置 AI API，也能通过固定格式完成基础记账；配置便宜模型后，可以自然语言记账。图片识别按实际能力启用。金额、统计、图表、提醒和备份继续由代码完成。

## 1. 无模型模式

- [x] 首次配置允许选择“固定格式”或“固定格式 + AI”。固定格式模式只要求聊天平台凭证和存储位置，不要求模型 URL、API Key 或模型名。
- [x] 调整初始化和运行条件，确保无模型时仍能连接机器人、绑定用户、运行提醒及日周月账单。
- [x] 提供明确语法，至少支持下列命令；最终语法在使用说明中保持一致。

| 命令示例 | 行为 |
| --- | --- |
| `支出 20 餐饮 奶茶` | 记录支出，日期默认当天 |
| `收入 30 红包 妈妈红包` | 记录收入 |
| `退款 #123 12.8` | 关联指定原支出 |
| `修改 #123 金额 18` | 修改指定账目 |
| `撤销 #123` | 撤销指定账目，保留历史 |
| `今日账单` / `本月账单` | 查询账单 |
| `本月饼图` / `资金分布图` | 生成真实账目图表 |

- [x] 支持明确填写日期、账户及账户名称中的空格；给出简短示例，不强迫每条消息填写全部可选字段。
- [x] 缺失账户时遵循现有账本语义，不编造付款账户或余额。金额用整数分校验，拒绝无效日期、超额退款及不存在的编号。
- [x] 调用现有账本业务函数，保留渠道来源、去重、审计、事务和撤销行为，禁止绕过业务规则直接写数据库。
- [x] 固定格式解析结果唯一且合法时按现有规则执行；需要确认的操作继续确认。格式有错时提示具体问题，无模型时自由表达返回一个简短输入示例。
- [x] 网页账户、贷款、物品清单、图表、导出和备份在无模型模式下继续可用。

## 2. 输入路由与便宜模型

- [x] 两种输入方式共存：明确命令优先由规则处理，其他文字在 AI 启用时交给模型。错误的明确命令不能被模型重新解释后绕过校验。
- [x] 模型只输出结构化操作或追问，账本计算和最终执行由代码负责。含糊指代、退款对象不明确、助学贷款还款日期未知时追问，不猜。
- [x] 日常记账默认不使用思考模式，不开启联网搜索或代码执行，不主动升级到昂贵模型。
- [x] 推荐候选为 `qwen3.7-flash`；不能仅凭模型名称承诺准确率或兼容性。这个只是推荐，表现在github的readme文件里面，不表现在具体的脚本和页面中。
- [x] 保留原模型服务配置和本地会话。已有安装升级后不自动切换供应商、模型、推理设置或工作模式。
- [x] 按实际供应商接口适配 Responses / Chat Completions。保存准确的接口类型，避免每条消息重复试探多个接口；兼容现有 Responses 配置。
- [x] 控制发送的上下文和输出长度，只提供当前任务所需的历史、账目引用和待确认状态；不每次发送全账本，也不截断重要金额或待确认信息。
- [x] 模型故障不影响固定格式命令、网页操作、图表和提醒。模式切换不丢失账目、对话、图片草稿或待确认方案。

## 3. 图片能力按需启用

- [x] 分别记录文字、结构化输出和图片能力，状态至少区分“已验证”“不支持”“未验证”。
- [x] 使用虚构样例检查接口，不使用真实账单做连接测试；已有图片测试逻辑尽量复用。
- [x] 文字模型不支持图片时，允许保存并正常记账。用户发图时明确回复：当前模型不支持读图，请发文字或更换模型。
- [x] 无模型模式也明确告知未启用图片识别；三种账单图表照常生成和发送。
- [x] 网络故障、密钥错误、平台下载权限不足不能标记成“不支持图片”；分别报告原因，保留原消息以便重试。
- [x] 图片识别继续使用原图结构化提取，排除顶部汇总，保留明细对应的时间、商户和金额；疑似重复、缺年份或账户继续核对，明确确认后才入账。

## 4. 验收

- [x] 自动测试覆盖：未配置模型仍可初始化和运行、固定格式零模型调用、无模型自由输入提示、规则与模型路由、无效命令、金额精度、退款关联、重复消息、渠道来源和事务回滚。
- [x] 覆盖文字模型保存、图片能力未知/不支持、权限与网络故障区分，以及换模型后保留本地记忆和账本。
- [ ] 用隔离账本验收飞书和钉钉的无模型记账、图表和主动提醒；覆盖 Mac、Linux、Windows 的安装与重启。未完成的真实平台验收明确注明。
- [x] 用一组有标准答案的样例比较模型：奶茶、红包、连续修改、部分退款、转账与收入区分、月付还款、未知贷款日期，以及含汇总和重复行的账单图片。
- [x] 记录每个候选的准确性、追问行为、响应时间和实际 Token 用量。只有具备可用凭证时才实测 Qwen，未实测不能写成通过。
- [x] 所有验收数据与正式账本隔离，不自动导入用户截图，不改动现有财产和贷款记录，不向 Git 或安装包放入密钥。
